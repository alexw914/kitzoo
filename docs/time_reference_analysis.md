# mtime_core / mtime_inner 对比与实现范围

参考目录均来自用户提供的 `thor_thirdparty/analysis/`，分析其 `reconstructed`
公开头文件、架构说明及实现。本仓库实现通用行为，不保证原库 ABI 或二进制布局。
time 保持独立模块，不并入 os；使用 `kitzoo::time`、`<kitzoo/time.hpp>`。

| 参考能力 | 原 kitzoo | 补充接口 |
| --- | --- | --- |
| MTimeClock / MTimeStamp / MTimeDuration 单位换算和运算 | 只有 Stopwatch/Deadline 使用 chrono | TimeStamp / TimeDuration，标准 chrono 转换和运算 |
| MStructTime，纳秒日期 | 本地毫秒格式化 | DateTime，UTC/local 转换，可选秒/毫秒/微秒/纳秒格式 |
| 系统 UTC、steady 时钟 | 间接用于计时器 | utc_timestamp / steady_timestamp |
| Feeder 模拟时间 | 无 | FeederTimeline，线程安全 feed，零也有效 |
| Callback 带 key 时钟 | 无 | CallbackTimeline，string_view key |
| 自定义 Timeline | 无 | Timeline 虚接口，默认 Custom 类型 |
| MFR 相对时间、clock_diff 修正 | 无 | OffsetTimeline，线程安全有符号偏移 |
| MTime 一次初始化，全局实例 | 无 | Time 单例，第一次查询前允许一次显式初始化 |

## 修正的参考行为

- 原日期读取使用 UTC `gmtime_r`，反向构造却使用本地 `mktime`，且有 32 位
  秒值截断。新接口显式指定时区，UTC 使用 C++20 日历，测试覆盖 2040 年及
  纳秒表示的完整边界。Local 使用 OS 时区，不修改进程 TZ 设置。
- 原时间值使用 uint64，负值、差值和溢出会回绕。采用有符号 chrono 纳秒；
  日期构造、偏移修正和等待目标的内部运算显式检查范围。
- 原 feeder 用 `timestamp > 0` 判断有效，无法表达零作为初始模拟时刻。
  新实现单独保存是否收到样本。
- 原 sleep 以 steady clock 等待并忽略 timeout。新 Timeline 等待跟随模拟
  时间进度，以 steady clock 实现真实超时，同时支持 stop_token 中断。
- 回调在 Time/Watcher 锁外调用；作用域析构不传播异常，显式 finish 可传播。
  结果记录在 scope 创建时预先分配，避免析构分配 map 节点。
- PTP 失败不伪装成零时间戳；返回 optional。设备时钟不自动解释为 UTC。

## 平台与依赖边界

日历、普通时钟、时间线和 Watcher 使用 C++20 标准库，适用于 Linux、macOS、
Windows；本地日期用 localtime_r/localtime_s，具体日期范围由 OS C 运行库决定。
PTP 只在 Linux 实现；其他平台返回 nullopt，不假装读取系统 UTC。

mtime_core 的 TimelineMFR 依赖 MFR 订阅 `/clock`、`/clock_expect`、`/clock_diff`
以及 TimeManagerConsumer 的共享内存协议。仓库没有这些 SDK 和运行环境，
不复制协议、不引入 SDK。应用层可把订阅数据 feed 到 FeederTimeline，并用
OffsetTimeline 添加修正。原 TimelineRos 是无效占位实现，不移植此占位类。

现有 Stopwatch、Deadline、Timer 保留，不重复增加另一套耗时工具或计时宏。
真实 PTP 设备、MFR/ROS 和框架共享内存集成需在对应环境另行验证。
